# テスト戦略（スタック非依存）

> テストランナー・アサーションライブラリ・テスト DB の接続先など具体はプロジェクトの `.claude/rules/` と `CLAUDE.md` が定める。本スキルは方針のみを示す。

## 層別のテスト種別

| 層 | 種別 | 方針 |
|---|---|---|
| domain | ユニット | エンティティ / 値オブジェクトの不変条件・等価性を純粋にテスト。依存ゼロなのでモック不要 |
| application（usecase） | ユニット | リポジトリ interface と port を **fake / stub で注入**して usecase を単体検証。DB・外部 I/O に触れない。**最重要** |
| infrastructure（リポジトリ） | インテグレーション | 専用テスト DB に対して実クエリを検証。ハッピーパス + 制約違反 |
| presentation（入口 / middleware） | インテグレーション | 入出力スキーマ、認証 / 認可の境界、エラーマッピング |
| frontend | コンポーネント | loading / error / empty 状態、ユーザー操作 |

## 原則

- **usecase の単体テストを最重要**とする。DI で fake を注入できる設計はテスト容易性のためでもある。
- インテグレーションテストは **専用テスト DB** を使い、開発 / 本番 DB を使わない。テスト間で状態をリセットし、実行順序に依存させない。
- 時刻は fake `Clock`（固定時刻）を注入して決定的にする。

## 記述規約

- テスト名は `should <期待する振る舞い> when <条件>`（Python 等では `test_<振る舞い>_when_<条件>`）。
- Arrange-Act-Assert（AAA）で構造化し、関連テストはグループ化する。
- エッジケースを必ずカバー: null / 空、境界値、エラーパス。

## 必須カバレッジ観点

- **認可境界**: 未ログイン / 一般ユーザーによる管理操作 / セッション失効。
- **日付境界**: 基準タイムゾーンと UTC の変換で日付が変わる境界（深夜 0 時前後）。
- **ドメイン不変条件**: 無効値が domain に入らないこと。
- **入力スキーマ**: 正常値の parse 成功と、不正値（境界値 / null / 空 / 型不一致）の parse 失敗。
- 重要な usecase は行カバレッジ 80% 以上を目安にする。

## テストが書けない設計への対応

テスト容易性のためにプロダクションコードの設計変更が必要な場合、テスト担当は自分で直さず、該当する実装エージェントへの**提案**として報告する。
